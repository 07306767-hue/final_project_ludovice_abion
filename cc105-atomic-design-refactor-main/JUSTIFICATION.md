# Justification — Atomic Design Refactor

I organized the app using Atomic Design by giving each widget a clear job. `Product` is the data model, not a UI level. Simple widgets such as `AppHeading`, `AppPrimaryButton`, and the product labels are atoms; groups like `CatalogSearchBar`, `ProductInfo`, and `ProductActions` are molecules. Larger sections such as `ProductCard`, `ProductCatalogList`, and `AddProductForm` are organisms because they combine widgets and handle local UI behavior. The form passes submitted values to the page instead of changing the product list itself. `CatalogPageTemplate` is a template because it arranges sections without knowing about product data. `CatalogPage` is the page because it owns the product list, updates it, and displays confirmation messages. This separation makes the code easier to understand and follows the activity rules.
